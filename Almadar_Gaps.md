- **G-ORBITAL-CORE-038** — The dispatch lane (`crates/runtime/src/kernel/lane.rs`) still lets an UNTOKENED call re-enter when it runs on the thread the RUNNING holder occupies. The parked refusal and the FIFO wait are keyed on an explicit `LaneTurn` (R-b1, 2026-10-21), and the kernel's own sub-dispatches carry the turn, but `orbital-server`'s `program/dispatch` substrate host (`ServerSubstrate::run`, `runtime.rs`) answers the ask in place with `dispatch_continuing`, and `SubstrateHandler::run(op, args)` hands it no turn to carry. Fix: pass the asking dispatch's `LaneTurn` to the substrate/service host (`SubstrateHandler::run` or `ServiceCaller`), have `ServerSubstrate` call `dispatch_in_turn`, then delete the `in_place` clause from `DispatchLane::enter`. `orbital-core-runtime` + `orbital-server` [architectural] — prevention rung: none of the language rungs (host concurrency), gated by the `tests/cross_trait_dispatch.rs` lane pins and `orbital-server` `go_as` program/dispatch tests. R-b1 (2026-10-21): a host answering a parked dispatch's ask in place now carries its turn and is refused (`control_an_unkeyed_program_dispatch_on_behalf_of_a_parked_dispatch_is_refused_not_hung`); the retiring `orbital-server` still answers an unkeyed `program/dispatch` in place without the turn, so it waits on its own parked dispatch (its three `program/dispatch` tests are `#[ignore]`d, covered by the core tests). Update 2026-11-07 (re-verified against source): orbital-server archived; live equivalent shell-rust runtime.rs. Severity: low. Root cause: K3.
