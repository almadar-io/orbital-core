- **One entry per gap:** `- **<code>** — <what is wrong and where>. <owning package> [mechanical|architectural] — <evidence, prevention rung>`.
- **Codes:** new gaps use this repo's prefix `G-ORBITAL-CORE-`. Take the "Next code" below, then bump it in the same edit. Codes are never reused or renamed.

- **G-ORBITAL-CORE-002** — `EmbeddedKernel::frame` costs about 0.11 ms per ticking trait. On the iOS simulator (iPhone 17 Pro, release C-ABI lib from `make ios-lib`), a frame with 100 ticking traits takes p50 11.4 ms and with 1 000 takes p50 557 ms / p95 752 ms, so every one of 600 frames misses the 16.7 ms budget and the R1-device frame gate (2 ms) by about 280×. Dispatch is fine (p50 0.15 ms over 10^4 events). Suspects: the frame path in `runtime/kernel.rs` and `effects/executor.rs` (per-trait entity layering, per-tick response building, render-store work per tick). Fix: profile one frame (allocation count + time per stage, like `tests/dispatch_alloc_count.rs`), then cut per-trait work so cost grows with traits that actually change. `orbital-core` [architectural] — evidence: `@almadar-io/parity` device rows (`frame-60hz-100`, `frame-60hz-1000`), `orbital-shell-ios/tests/device-bench/`; prevention rung: none of the language rungs (performance), gated by the device frame row.
- **Close by deleting.** Remove the entry in the same commit as the fix.

- **G-ORBITAL-CORE-009** — HTTP retry backoff caps the exponent at63 before saturating multiplication, so a positive base of1 remains2^63 at retry ordinal65 (exponent64) instead of saturating at u64::MAX. Owner: runtime/http_request.rs::next_retry_delay. Preserve base0 and exact earlier powers; reproduce through the actual driver with boundary controls before repair. Prevention rung: none of the language rungs (valid execution metadata arithmetic); canonical driver retry-boundary regression and host no-early-send controls. [mechanical]

- **G-ORBITAL-CORE-004** — `time/parse` (`src/evaluator/operators/system.rs`) is a hand-rolled day count: it ignores the time of day and the offset, miscounts leap days after February (`time/add (time/parse "2028-03-01") 1 day` yields 2028-03-01), and silently defaults unparsable parts to 1970/1 (a hidden fallback). Its arity is 1 while the std registry (`@almadar/std` `modules/time.ts`) declares a format argument. Fix: full RFC 3339 / ISO 8601 parsing with offsets, an explicit error on bad input, the same semantics in the TS evaluator twin, shared vectors. Evidence: calendar atom fixture `create-event-duration` (http program, 2026-10-15). Prevention rung: none of the language rungs (operator semantics); gated by shared operator vectors on both paths. `orbital-core` + `@almadar/evaluator` [mechanical]
- **G-ORBITAL-CORE-005** — An `http` (and `call-service`) `key` option resolves only a `@binding` path or a literal (`key: Option<String>`, `resolve_key` in `src/runtime/kernel.rs`); an expression such as `(str/concat …)` silently becomes null, though H.1 and `Almadar_LOLO.md` allow any expression. Fix: the key is an evaluated expression on both paths; a key that does not evaluate to a string is an error. Evidence: calendar atom worked around it with an entity `callKey` field (2026-10-15). Prevention rung: `orb validate` (a key expression the runtime cannot evaluate must be refused, never nulled). `orbital-core` [mechanical]

- **G-ORBITAL-CORE-014** — Runtime type enforcement checks an array argument only by its first element, so `(array/flatten (list [] x))` passes a declared `[T]` when `x` is an object. orbital-core evaluator / `@almadar/evaluator` [architectural] — evidence: the std-arxiv entry-list workaround for a single-child `xml/parse`; prevention rung: `.lolo` types (an array value is checked element by element, in both runtimes).

- **G-ORBITAL-CORE-015** — `xml/parse` cannot honor the declared shape's list fields: the IR carries only the shape NAME (`["xml/parse", s, "ArxivFeed"]`), the evaluator (`BindingContext`), the TS evaluator and the TS codegen have no type declarations, so a single child element becomes an object where the shape declares `[T]` (std-storage `s3-object-round-trip#7`: "expected array, got object" on one `<Contents>`; std-arxiv wraps it with `array/flatten`). orbital-core + orbital-compiler + @almadar/evaluator + orbital-shell-typescript [architectural] — fix needs the resolved shape inlined into the call at validate/enrich time (or a type registry in every evaluator); prevention rung: `orb validate`.
